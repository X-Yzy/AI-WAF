## 误报修复

修复前完整链路有156个误报，主要来自：

- HTML教程中的实体编码 `<script src=...>` 被当作执行载荷；
- `%40n` 等URL编码被误判为printf `%n`写入；
- 参数化SQL和多语言SQL讨论被模型误判。

最终实现仅放行带明确教程/文档标记且源码保持实体编码的展示文本；
格式规则保留明确 `%n` 和位置参数 `%1$n`，模糊宽度形式交给模型；
参数化SQL使用严格语法模式，多语言讨论仍拒绝活动攻击结构。修复没有
改变最终测试集攻击召回数量。

完整样本、规则计数、层级分布和时延见
`models/current/pipeline_evaluation.json`。

## 真实 WAF 产品对比

对照组不再使用安全狗/D盾/云锁关键词画像，而是实际运行官方固定镜像
`owasp/modsecurity-crs:4.28.0-nginx-202607160307`：ModSecurity 3.0.16、
OWASP CRS 4.28.0、Nginx 1.30.4。配置为规则引擎 `On`、PL1、入站异常阈值 5。

34,721 条同集结果：

| 系统 | Precision | Recall | F1 | FPR | 原始攻击 Recall | 混淆攻击 Recall |
|---|---:|---:|---:|---:|---:|---:|
| 最终 AI-WAF | 99.0476% | 98.8515% | 98.9495% | 0.0745% | 98.8014% | 98.8946% |
| ModSecurity + OWASP CRS | 40.1990% | 52.7921% | 45.6429% | 6.1592% | 88.4418% | 22.1076% |
| open-appsec 1.1.35-open-source | 30.1199% | 76.5941% | 43.2372% | 13.9365% | 92.8938% | 62.5645% |
| SafeLine CE 9.3.11 | 92.4107% | 57.3861% | 70.8038% | 0.3696% | 61.9863% | 53.4267% |

四个系统指标来自 2026-08-01 01:24:37（Asia/Shanghai）的本次全量同集实测；
最终 AI-WAF 和三款真实产品都在相同 34,721 条记录上重新执行。

ModSecurity 产品混淆矩阵为 `[[30213,1983],[1192,1333]]`。产品端实际响应为 31,405 个
后端证明 `204`、3,313 个 `403` 和 3 个 `400`，合计精确等于 34,721；不存在
以超时、5xx 或连接错误代替检出的记录。638 条不能表示为单个合法 HTTP/1.1 header
字段的记录被显式映射为 form body，数量和原因保存在报告中。

Windows Docker Desktop 长跑发生 2 次可恢复传输停顿。适配器没有将其计为阻断，
而是在同一个宿主证明后端和端口上启动同一镜像摘要的新容器、通过普通请求/SQLi 双冒烟
门禁后重放同一记录；所有恢复事件均在 `product_execution.restart_events` 中，启动阶段
异常单独记录在 `startup_failures`。每 1,000 条保存包含数据清单、模型和镜像签名的原子
检查点；重新点击只在签名完全一致时继续，成功后自动删除。

AI-WAF 延迟是进程内推理，真实产品延迟包含 loopback HTTP、Nginx、ModSecurity 和
后端证明，因此效果指标可同集比较，纯引擎延迟不能直接比较。完整产品身份、镜像摘要、
配置、状态码、分类型召回和公平性声明见
`models/current/waf_comparison.json` 与 `docs/experiments/REAL_WAF_COMPARISON.md`。
